# 环境验证与运行诊断

本模块操作 CLI 安装、运行组件、配置和服务连接。业务失败与业务操作状态由相应领域接口处理。

## 诊断接口

| 操作               | 行为                                                           |
| ------------------ | -------------------------------------------------------------- |
| `--version`        | 返回 CLI 包版本。                                              |
| `runtime describe` | 返回安装包、Node、平台和资产身份；不加载业务配置、不下载组件。 |
| `doctor`           | 检查本地运行版本、平台、必需组件、配置完整性和冲突。           |
| `doctor --online`  | 在本地检查之外，对明确的目标服务执行有界连接检查。             |

默认诊断只读。每项结果记录检查对象、观察值、状态和原因；未检查项单独返回。配置只显示定位问题所需的非秘密信息。在线诊断不得派发数据写入、计算、审核或发布。

诊断成功仅证明检查范围内的条件满足。账号在线核验使用 `auth whoami` 或 `auth doctor-auth`；业务权限继续由具体服务检查。

## 返回上下文

诊断采用 [AI 上下文契约](ai-context.md)，返回检查范围、实际安装与目标、未检查项和脱敏配置来源。推荐与已观察问题对应：缺认证条件可指向 `auth doctor-auth`；业务对象错误应指向该对象的查询或报告。

诊断命令不能因发现问题就自动安装、清理或修改配置，也不能把模板中的修复建议描述为已完成操作。没有可验证的修复入口时返回具体缺口，不生成猜测命令。

## 配置选择

官方环境使用 CLI 提供的公共配置。显式定制环境必须提供完整匹配的目标、公开密钥、OAuth 客户端与回调配置；不把官方配置片段补到其他目标。短期访问令牌模式必须显式绑定目标和公开密钥。

命令级显式目标优先于环境配置，但必须通过完整性和会话绑定检查。目标变化不能复用绑定其他环境的会话或恢复记录。诊断结果返回实际解析的目标与配置来源。

## 独立运行支撑

| 入口 | 责任 |
| --- | --- |
| `runtime ensure` / `runtime status` | 按精确清单准备或检查运行组件。 |
| `runtime prune` / `runtime lease-release` | 显式管理缓存与租约，保留活跃执行需要的资源。 |
| `runtime exec` | 在已验证的运行环境启动明确命令，遵守独立的子进程输出和退出协议。 |
| `pcr snapshot ensure` / `pcr snapshot status` / `pcr exec` | 固定和使用方法工具快照，绑定精确内容身份。 |

这些入口属于运行支撑，帮助信息单独分组。组件准备、租约和工具快照不授予数据写入权限，不决定科研结论，也不承担业务任务状态。诊断不得隐式调用安装或清理操作。

```bash
tiangong-lca runtime describe --json
tiangong-lca doctor --json
tiangong-lca doctor --online --json
```
