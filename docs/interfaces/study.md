# Study 建模研究与计算

Study 围绕产品或其他分析对象组织 LCA 建模研究，将用户提供的资料逐步转化为有来源依据、边界明确、连接确定且可以计算和解释的模型。本文件定义该流程对 CLI 的目标能力要求及职责边界；Skill 实现由 agent-skills 所有，计算与服务契约由相应领域仓库所有。实现差距在[实施计划](../plans/cli-0.2.0-refactor-plan.md#model-计算后续实施)维护，本文件不表示现有命令或 Skill 已完成该流程。

## 对象与职责

| 对象或组件 | 职责 |
| --- | --- |
| Study 研究对象 | 保存研究目标、范围、资料索引、已确认事实、假设、缺口、选择依据及相关模型、运行和报告身份。 |
| Study Skill | 引导研究、调用可复用子 Skill、选择和组合 CLI 操作、解释结果并安排必要修订。 |
| Process | 表达一个前景过程或明确选用的背景过程的交换清单、参考产品、单位和边界。 |
| Model | 明确本次计算包含的过程实例、连接及系统边界；不隐含全库供应者搜索。 |
| Calculation / Run | 固定一次计算的输入、方法、参数、实际引擎版本和结果；模型修订不覆盖旧结果。 |
| CLI | 提供发现、读取、校验、内容处理、创建、保存和计算等可组合操作，以及真实状态和下一步上下文。 |
| Worker 计算组件 | 编译固定输入并执行数值计算；线上任务包装另行承担队列、租约、重试和存储。 |

Study 是完整研究流程的入口；单独计算一个已有 Model 无需先创建 Study。研究记录可以从本地开始，不因选择 Study Skill 就强制上传原始资料或建立线上项目。需要线上保存或协作时，显式选择持久化位置和范围；一次计算不能暗中创建项目来满足后端前提。

## 六个阶段及产物

| 阶段 | 工作 | 主要产物与进入下一步的依据 |
| --- | --- | --- |
| 1. 明确研究对象与目标 | 确定产品或服务、研究用途、功能单位、系统边界、地域、时间和关键方法选择。 | 研究定义、已有决定和待确认事项；先明确影响当前工作的选择，后续逐步细化。 |
| 2. 引导资料收集 | 围绕研究范围引导用户提供物料、产量、能耗、排放、工艺说明及相关文件。 | 原始资料与索引、覆盖范围、缺失资料；保留来源，不自动公开文件。 |
| 3. 提取与缺口分析 | 识别过程、物料和数值，核对单位、时间、产线、数量基准及证据冲突。 | 带来源位置的数据表、转换依据、缺口、假设及具体补充问题；未知值不能替换成零。 |
| 4. 建立前景过程 | 根据用户数据建立 Process 草稿和前景模型结构，通过 CLI 查询 Flow、属性、单位及其他需要的参考数据。 | 可追溯的交换项、参考产品、适用分配及显式前景连接；校验发现和未解决问题可见。 |
| 5. 选择并连接背景过程 | 通过 CLI 搜索、读取和比较背景候选，选择适用的精确版本，连接前景模型。 | 完整 Model、背景选择依据、覆盖边界和必要的显式截断；不按搜索分数自动接受候选。 |
| 6. 计算与分析 | 准备固定输入，执行模型计算，读取结果并解释贡献、覆盖和假设的影响。 | 绑定具体模型及输入的运行记录、结果、诊断和按需生成的报告；执行成功与科学有效性分别表达。 |

数据提取必须保留数量的统计口径。例如，年用电量需要同时记录对应时间、产品产量和生产范围，才可形成每功能单位输入。数据转换保留原值与推导关系，不能把模型假设写成用户提供的事实。

这六个阶段允许迭代，不构成必须逐次重跑的流水线。已有资料和模型可以复用；补充问题只针对影响研究或当前操作的缺口。无法解决的缺口应记录其影响，并根据研究目标阻断、缩小范围或明确采用有依据的假设，不能静默跳过。

## 子 Skill 与研究上下文

资料收集引导和资料提取与缺口分析是两个可独立复用的 Skill 职责。Study 传入当前研究定义、已有资料和相关问题，子 Skill 返回明确的资料索引、提取数据、来源及待补事项，不分别维护另一套研究状态。

前景建模和背景选择保持可识别的阶段，按实际复用需求决定是否再拆为独立 Skill。拆分不要求新增 Agent 调度系统，也不把流程编排迁入 CLI。

研究上下文至少保留目标、当前阶段、资料位置、事实与假设、未解决问题、模型版本、背景选择以及运行结果的关联。它可以由文件与已有业务记录承载，不预先增加复杂工作流 schema。原始材料、提取表、模型和结果各有职责；来源修订时回到受影响的最早环节，标记相关模型和旧结果对新输入不再适用。

## 背景过程与显式连接

Study 从 `state_code=100` 的 Process 中选择线上背景候选，再通过独立的计算结果读取通道取得该精确过程版本对应的聚合 LCI 清单。`LCI result` 类型字段不是筛选条件，Process 详情中的原始 exchanges 也不等于其上游聚合结果。数据集身份与计算结果身份分别保存，不能把二者混为一个对象。

结果服务负责解析 Process 与已发布计算产物的关系，并按其 HDF5 查询契约返回参考量、资源消耗、排放及可用的 LCIA 指标。若服务先返回独立结果对象，准备操作必须保留该结果身份和来源关系，不将 Process ID 当作结果行 ID；有多个可选结果时明确选择，不默取第一项。

- 背景输入必须具有明确参考产品、单位及数量基准、完整聚合 LCI、精确 Process 版本、结果及产物身份、来源和覆盖范围。
- 分页读取固定同一发布与产物，沿游标读取到结束并校验完整性；不能把筛选后的展示页作为完整计算输入。结果未就绪、无对应结果、读取失败与经过完整性验证的零清单分别表达。
- 在选定清单的边界内按参考量缩放；以已经完成聚合和分配的清单使用，不再展开原始组成过程或重复施加已经完成的分配。
- 仅有碳足迹等 LCIA 指标分数的结果不作为这种清单输入，不将已表征指标再当作基本流进行表征。
- 来源、原始过程和引用关系用于追溯，不自动变成计算依赖边。已有聚合清单包含的上游负荷不得在同一需求路径再次叠加；独立的其他需求可以复用同一过程。
- 背景仍有未闭合的技术系统需求时，须在建模阶段明确连接或声明截断及影响，不能假定存在 HDF5 结果就代表其边界覆盖所研究的完整生命周期。

Agent 根据产品、功能、单位、技术、地域、时间、系统边界和数据质量比较候选，选择后将精确 Process 版本和交换端口写入 Model，并在计算输入中固定所用聚合结果；同一需求明确采用原始过程展开或聚合结果，不能同时叠加。存在影响结果的歧义时请求用户决定；已有充分依据和授权的选择无需重复确认。

Worker 只计算已经建立在 Model 中的过程与连接。线上与本地均不自动扫描数据库寻找 provider。准备阶段读取模型已经引用的数据属于依赖解析；搜索、选择和新增供应关系属于建模决策，二者不得混同。

## 计算及运行位置

线上 Model 默认提交线上任务，本地 Model 或完整输入包默认本地执行。背景数据最初来自线上，不会让已经准备好的本地 Model 自动改为线上计算。获取背景数据与选择计算位置是两个独立动作。

完整输入包固定 Model、所选 Process 及背景聚合 LCI、必要的 Flow/属性/单位、方法因子及功能单位和计算设置。线上结果先经显式准备操作读取、验证并固化为本地输入，随后离线计算；HDF5 是结果服务的存储和读取实现，不要求本地引擎连接该服务或下载整个数据库。计算内核无需业务数据库或队列；本地执行器管理进程、预算和产物，线上任务服务管理受理、调度及恢复。引擎配置、资源预算、状态、结果和失败处理统一遵循 [Model 计算设计](calculations.md)。

单供应者端口、明确单位关系和分配等属于所选计算契约的建模规则；实例数、输入大小、内存、线程和超时属于工程预算。不能通过放宽预算改变科学语义，也不能将固定容量误写为 LCA 建模规则。

## 校验、迭代与发布边界

CLI 和 Worker 负责结构、引用、连接、单位、数值与完整性等确定性检查；Study/Agent 负责资料解释、适用性选择和研究结论。计算完成不自动构成科学审核或可公开结论。

| 新发现 | 返回的环节 |
| --- | --- |
| 数量口径不明、证据冲突或重要数据缺失 | 资料提取或用户补充，保留原证据与修订原因。 |
| 背景候选不适用、单位不匹配或连接未闭合 | 前景建模或背景选择，更新明确的模型关系。 |
| 方法因子缺失或截断影响重要 | 核对流及方法匹配、背景覆盖与研究范围；不因原始分数为零而声称无影响。 |
| 贡献分析显示某项假设主导结果 | 补充相关证据或建立显式替代情景，仅重算受影响的模型。 |
| 本地资源不足或线上任务失败 | 对应执行器的配置、查询或恢复路径，不自动改变模型或科学规则。 |

本地草稿、线上私有保存、数据集审核、报告审核和公开发布分别表达。研究中创建前景 Process 不意味着必须将其公开入库；调用 `create/save` 只完成声明的保存动作。用户只要求建模计算时，流程完成于可解释结果，不自动推进到审核、报告分享或发布。

## CLI 能力边界

数据发现必须能明确选择当前账号或获准访问的背景数据范围，返回精确身份和实际可见范围。详情应支持判断清单类型、参考产品、单位、系统边界、覆盖和适用性；缺失信息如实标明。候选、可读、可用于计算是不同状态，不能用一种成功替代另一种。

Process 与 Model 使用现有对象职责进行查询、校验、编辑和显式保存；计算通过 Model 入口发起，以独立 Run 读取结果。背景计算采用“状态 100 Process 发现—精确版本结果解析—完整 LCI 读取—固定输入—模型计算”的一致契约，现有保留状态的普通数据集准入规则不因此放开。当前命令和 Skill 的具体迁移由相应所有者实施，不在 CLI 新增“一键完成研究”的隐藏编排。
