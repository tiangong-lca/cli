# 接口通用约定

本契约适用于本轮定义的[目标接口](README.md)。Release 保持现有参数、结果和恢复契约，本轮不适用新的统一接口要求。运行支撑的子进程透传协议遵守其独立契约，不改写被启动程序的输出。

## 输出协议边界

根命令的 `--help --json` 声明各命令族的机器帮助和结果协议。统一结果信封适用于 Doctor、Auth、按类型的 Dataset 与 Review 核心操作，以及目标 Model 计算和 Calculation 查询接口；后者的实施范围见[Model 计算后续实施](../plans/cli-0.2.0-refactor-plan.md#model-计算后续实施)。已有 Study 使用独立的版本化结果及错误协议；runtime/PCR 使用各自的描述、管理与固定快照协议，执行子进程时保留子进程 stdout、stderr 和退出语义。Release、普通维护、管理员及整包工具保持其独立契约。

外层 `--json` 可以放在命令名称前；它仍属于 CLI 包装层，不能跨过 `--` 成为被启动程序的参数。不接受该选项的执行协议应拒绝它。保留协议的文本帮助通过普通 `--help` 发现，不能因收到 `--json` 就假设其输出满足核心结果信封。

## 输入与能力发现

- 简单选择使用参数，结构化请求使用 `--input <file>`，`--input -` 从标准输入读取同一结构。
- `--json` 返回机器结果；`--output <path>` 写业务内容或大产物；`--force` 仅允许覆盖本地输出，不能覆盖业务冲突或权限失败。
- 输入路径相对当前工作目录解析；请求文件内的相对文件引用相对该请求文件解析。标准输入中的文件引用必须为绝对路径。
- 输入与输出不得指向同一文件。默认拒绝覆盖已有输出，业务请求不能依赖私有任务目录或固定阶段文件名。
- 远程变更通过动作名显式发起；`--dry-run` 只验证输入和可读取的前置条件，不发送变更请求，不产生已受理记录，也不授予后续执行权限。
- `<command> --help` 说明用途、输入、效果、错误和示例；`<command> --help --json` 返回该命令的契约版本、参数、请求及结果 schema、能力限制与恢复方式，不执行业务操作。

各类型的 `contract` 返回数据内容 schema、规则集和来源版本。命令请求 schema 与 TIDAS 数据 schema 分别发现；不能用数据结构合法替代命令前置条件。

## 结果

`--json` 模式 stdout 只包含一个结果对象；业务失败也使用相同结构，stderr 只输出脱敏诊断。二进制和大内容通过文件交付。

| 字段 | 语义 |
| --- | --- |
| `schemaVersion` | CLI 结果契约版本，与业务数据版本独立。 |
| `operation` | 实际执行动作的完整主命令名称；别名调用归一到同一主命令。 |
| `status` | `completed`、`accepted`、`partial`、`failed` 或 `unknown`。 |
| `outcome` / `summary` | 稳定的具体结果语义，以及根据实际事实生成的一句摘要。 |
| `data` | 业务结果，包含实际解析的对象身份、状态及必要的内容绑定。 |
| `context` | 当前主体、环境、观察来源与时间、实际输入、默认值和适用的请求身份。 |
| `completeness` | 查询范围、截断、分页和未执行检查；不适用的值为 null。 |
| `artifacts` | 文件路径、用途、大小及可用的内容摘要。 |
| `warnings` | 有界的结构化提示，不替代阻断错误或完整性标记。 |
| `error` | 失败类别、稳定错误码、可公开原因和相关输入位置；成功时为 null。 |
| `nextActions` | 简短的下一步提示；每项包含 `description` 和可选 `command`，没有后续时为空数组。 |
| `replyTemplate` | 一份 Markdown 回复指导的文件路径字符串。 |

上下文、推荐命令与模板的详细契约集中于 [AI Friendly 上下文设计](ai-context.md)，表达正文见[回复模板](reply-templates/README.md)。它们从同一份结果派生，不能形成另一套业务状态或新的审批要求。

校验结果使用 `data.validation.status` 返回 `passed`、`failed`、`incomplete` 或 `not_applicable`，并在 `data.validation` 中附规则、内容身份及发现。命令正常完成不等于数据合格。异步请求受理返回 `accepted`，不能报告业务完成。

退出码：`0` 表示调用成功且没有必需的失败或未完成检查；`2` 表示命令、参数或请求结构无效；`1` 表示业务失败、必需校验未通过、部分完成或结果未知。自动化应以结构化状态和错误码判定具体原因。异步受理可返回 `0`，调用方继续检查业务状态。

## 身份、并发与恢复

远程变更绑定环境、执行账号、对象、输入内容和请求身份。调用方持有的预期修订或等价前置状态由服务端验证。业务版本不能替代并发控制凭据；本地哈希不能自行成为服务端写入授权。

错误类别至少包括输入无效、对象不存在或不可见、认证失效、权限不足、冲突、业务条件不满足、能力不支持、服务不可用和执行结果未知。不存在与不可见是否可区分遵守服务端披露规则。

超时不代表没有产生效果。变更请求必须提供原请求的查询、独立读回或受支持的幂等恢复路径。恢复信息应在派发前持久化；凭据不得进入结果、日志或恢复产物。没有幂等保证的写入不得自动重试，也不得换账号、环境或内容恢复。

幂等重放返回原结果；它不能将另一份内容视为同一请求。任何操作都不能在失败后静默转为权限更宽、前置条件更弱的执行路径。

## 批量与异步

只有能力声明包含批量模式的命令才接受批量输入。每项包含稳定的 `itemId` 和请求内容；结果保留逐项身份、结果和恢复信息。支持的并发上限由命令能力声明给出，同一对象的写入必须序列化。

批量默认不保证整体事务。跨项依赖由调用方安排；停止派发后等待已派发项结束或记录未知结果，不把它们视为未执行。重复执行只处理已确认可以重试的项。

异步返回可查询的领域对象或操作标识及准确的查询动作。等待有界，超时保留可继续查询的身份；只在领域服务支持时暴露取消操作。不建立通用的 Agent 任务状态机。

## 本地与远程边界

本地规则检查与确定性转换无需业务登录。远程引用检查、附件传输和数据写入必须显式声明所需身份与范围。未执行的检查不能标记为通过。

本地输出原子替换只保证该文件的可见性，不代表多个文件、多个远程请求或多个数据集构成事务。文件产物写入失败时保留原业务结果与恢复身份，不能重新执行已完成的变更来补文件。
