# AI Friendly 上下文设计

CLI 每次返回准确的业务结果，并提供简短的下一步提示和回复模板。AI 根据真实结果组织回复、选择后续操作，无需先理解一套额外的执行或模板协议。

本契约适用于本轮核心接口。这里的“节点”指一次原子操作及其观察到的业务状态。Release 沿用现有接口。

## 事实与提示的分工

业务结果保留[通用约定](conventions.md)中的结构化状态、对象身份、范围、完整性、错误和产物。推荐命令与回复模板只帮助调用方理解和继续操作，不定义业务成功条件或授予权限。

| 内容                 | 表达方式                                                    |
| -------------------- | ----------------------------------------------------------- |
| 发生了什么           | `status`、`outcome`、`summary` 及 `data` 中的实际业务结果。 |
| 使用了什么输入与范围 | `context` 中的实际输入、默认值、精确对象及观察信息。        |
| 可以怎样继续         | `nextActions` 中的简短说明及可选命令。                      |
| 怎样向用户说明       | `replyTemplate` 引用的一份 Markdown 表达指导。              |

## 下一步提示

`nextActions` 是一个简短列表，每项只包含：

- `description`：说明下一步做什么；需要补充输入或作出选择时，直接写明缺什么。
- `command`：可选的、已经带有具体参数的命令字符串。没有完整可用命令时省略。

```json
{
  "nextActions": [
    {
      "description": "查看审核进度和成员状态",
      "command": "tiangong-lca review get --id review-123 --json"
    }
  ],
  "replyTemplate": "/opt/tiangong/assets/reply-templates/operation-accepted.md"
}
```

需要选择时使用同一形式，不再增加独立的决定对象：

```json
{
  "nextActions": [
    {
      "description": "找到两个名称相近的 Flow，请根据返回的版本和单位信息选择要使用的对象。"
    }
  ]
}
```

候选数据仍放在业务结果中。没有后续动作时返回空数组。默认最多返回三个有价值的提示，不强制每次操作都推荐下一条命令。

### 命令生成规则

推荐由当前真实状态生成，命令必须使用实际对象、精确版本、游标和存在的文件。需要文件路径或工作目录时，使用可直接定位的绝对路径，或在命令中明确目录；按当前平台正确处理引号和空格。不输出猜测入口、占位参数或凭据。

Windows 推荐命令面向 PowerShell，其他平台面向 POSIX shell；引用规则随平台选择。标准输入不能作为已经可重取的文件路径：续页需要原内容时只说明如何保存同一内容并使用返回游标，不生成假定 stdin 仍可重读的命令。

- 已受理且业务尚未完成时，首先推荐查询精确对象或请求状态。
- 写入结果未知时，首先核实原请求或独立读回，不推荐重新创建、再次提交或切换账号。
- 版本、内容或审核范围冲突时，先读取当前状态或重新预览，不自动覆盖或缩小范围。
- 有下一页时，推荐保留过滤、排序与游标的继续读取命令。
- 多个候选需要选择时说明差异，不默认采用第一条；已解析的 `latest` 在后继命令中使用实际版本。
- 缺少请求内容、能力或必需条件时，只说明具体缺口或给出可用的帮助、查询命令，不编造输入文件。
- 用户请求的目标已经完成时可以结束，不自动延伸到审核、发布或整个生产流程。

这些是命令生成和实现验收规则，不需要增加输出字段。推荐是给调用方的提示，不是自动执行脚本。调用方继续遵守实际权限与请求范围；已有适用的用户决定直接复用，不重复确认。

## 回复模板

`replyTemplate` 只返回一份模板文件的路径字符串。实际运行时使用当前安装包中可读取的绝对路径；示例路径仅说明形式。模板随 CLI 安装包分发，调用方无需工作区源码或 Release workflows 仓库。

模板是一份简短 Markdown，说明怎样表达本次结果、哪些事实需要保留，以及容易混淆的状态。AI 读取本次指定文件后，根据真实结果组织回复，无需固定占位符或机械填表。

模板按沟通语义复用，见[回复模板目录](reply-templates/README.md)。查询、校验、预览、完成、受理、冲突、部分完成和结果未知分别处理；具体类型的业务事实仍由领域结果提供。版本查询、纯帮助和子进程透传不需要模板。

模板文件由 CLI 自身选择，数据对象、附件或上游错误消息不能指定任意模板。模板只能指导表达，不能改变执行规则。缺少模板时返回提示并按事实摘要回复，不改变业务结果或重放已经产生效果的操作。事实缺失时说明未确认或未执行，不补造值。

## 保留必要上下文

`context` 只保存继续操作需要的事实，不复制整个请求或响应：

- `subjects`：精确对象、版本、修订，以及适用的审核单、轮次和包身份。大成员集合通过清单产物提供。
- `environment`、`actor`：必要且脱敏的执行目标和账号；纯本地或匿名操作明确标记不适用。
- `observation`：观察来源和时间。缓存、现场查询和写入回执分别表达，不能用旧摘要替代当前事实。
- `effectiveInput`：影响范围和效果的实际输入，例如 `dry-run`、`includeRelated`、检查范围及版本解析结果。
- `defaultedInputs`：由默认规则产生的值及来源。例如未指定 `includeRelated` 时，明确返回采用 `true`。
- `requestId`：适用时返回原请求身份；未知结果保留已有恢复记录引用。

业务细节放在 `data`，上下文保留关键选择与身份。调用方保存本次结构化结果即可交接；下一次操作仍要验证当前状态和权限。

## 摘要与按需读取

人类模式与 JSON 使用同一份业务结果。人类输出先说明本次结果，再给出必要身份、完整性和下一步提示；需要 AI 组织回复时提供模板路径。没有下一步时不补造流程。

默认展示简短摘要和最多五条代表性发现，其余通过分页或报告文件读取。必须保留发现总数、所有阻断类别和完整报告入口，不能因为省略详情而报告通过。完整 Dataset 内容不能截断后伪装成可再次保存的数据。

全局帮助列对象和能力；命令帮助说明最小输入、效果和常见失败；`--help --json` 提供业务调用契约；类型 `contract` 提供数据内容规则。调用方只读取当前命令、当前模板和所需产物。

## 实现验收

- JSON、人类摘要和模板回复表达相同的实际状态，明确区分保存、受理、审核完成和发布。
- 推荐命令带有真实参数，正确处理路径和引号；没有可用命令时用说明表达缺口。
- 未知结果、冲突、分页和预览分别返回适合当前状态的提示，不盲目重试或自动推进业务。
- 模板路径在安装后可读取，模板缺失不改变业务事实；模板正文不依赖固定字段注册或占位符解析。
- 实际默认值、范围和未执行检查可见；已有用户决定不触发重复审批。
