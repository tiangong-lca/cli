# Model 计算

本文件规定目标接口。模型来源决定默认执行位置：线上精确版本的 Model 提交线上计算，本地 Model 文件或完整计算输入包使用本地执行器。计算不修改模型，不自动保存数据集、提交审核或发布结果。实现范围及与已发布 Study 接口的差距由[实施计划](../plans/cli-0.2.0-refactor-plan.md#model-计算后续实施)维护；下列命令形式用于定义目标接口，不是现有版本的执行教程。

## 业务对象

| 对象 | 职责 |
| --- | --- |
| Model | 被计算的系统，包含过程实例、连接和交换关系；线上引用必须定位精确版本，本地输入必须固定实际内容。 |
| Calculation / Run | 一次计算的独立记录，绑定模型内容、完整输入、功能单位、方法、参数、实际引擎版本及结果。 |
| Study | 围绕分析对象组织目标、资料、前景建模、背景选择、情景、运行及报告的研究对象；完整流程见 [Study 总体设计](study.md)。 |

一次计算不要求调用方先创建 Study。加入 Study 必须显式声明目标和关系，不能在后台创建未披露的项目来满足服务前提。不同功能单位、方法或参数产生不同的计算记录，不能覆盖 Model 上的单一“当前结果”。计算执行完成与结果有效性、方法覆盖和科学审核分别表达。

`dataset model build-resulting-process` 生成候选 Process 内容；Model 计算生成计算记录和结果，二者不互为别名。顶层 `review` 管理数据集审核，`study review` 管理精确报告版本的审核，权限与状态分别归各自领域服务。

## 来源与执行选择

| 模型选择 | 默认执行方式 | 调用成功的含义 |
| --- | --- | --- |
| `--id <model-id> --version <version>` | 在选定服务提交线上任务。 | 服务确认受理并返回计算及任务身份；尚不代表计算完成。 |
| `--file <path>` | 在当前运行环境执行本地计算。 | 输入和运行环境检查通过后执行；计算完成并交付产物才报告完成。 |

两种来源互斥，缺少来源或同时指定来源必须拒绝。文件内容带有线上 ID 不改变本地来源选择；线上对象存在本地缓存也不改变线上执行选择。线上精确版本仍须绑定实际采用的内容快照，不能仅凭版本字符串假定草稿不可变化。

默认路径失败时不得改换执行位置、引擎、账号或模型版本。本地计算不得隐式上传输入；线上计算失败不得自动下载模型改为本地运行。

跨位置使用通过明确的数据交付和授权边界完成：线上模型先显式导出完整计算输入包，随后作为本地输入；本地内容交给线上服务需要独立声明的上传或提交能力。默认计算命令不隐式承担这些操作，跨位置能力不属于首阶段实现范围。

## 输入准备

Model 文件不等于完整计算输入。准备阶段必须解析精确引用并检查所需的 Process、Flow、属性、单位、LCIA 方法与因子等依赖，以及功能单位、参数、截断和适用分配设置。实际依赖集合由领域契约与引擎能力决定。

- 完整输入包固定模型、依赖内容、来源身份、方法版本、计算设置及完整性信息；引擎选择另有精确记录。
- 本地计算只消费显式提供的输入与声明的本地依赖。缺失内容时返回具体依赖及可继续操作，不自动登录、联网下载或选择最新版本。
- 需要远程获取依赖时，由显式准备操作执行认证、访问和内容固定；准备成功不能被报告成计算完成。
- 线上任务可由其服务按声明的契约完成输入准备，必须保留准备状态、采用的精确依赖及诊断。计算内核只接收准备完成的输入。
- 结构合法、引用完整、数值可计算和方法覆盖是不同检查。缺失因子、截断项及不支持条件由所属规则明确表达，不能静默补零或简化模型。

## 显式模型与背景聚合清单

线上与本地使用相同的显式连接规则。输入准备只解析 Model 已声明的过程、连接和必要数据引用，不自动寻找 provider、不自动扩展上游。非零未连接需求须明确补充模型连接或声明截断及影响，否则返回可定位诊断。Agent 在建模阶段搜索并选定供应过程属于显式建模，不属于 Worker 自动连接。

符合[背景聚合清单契约](study.md#背景过程与显式连接)的 Process 可以作为背景计算输入，包括具备该内容及使用资格的 Result Process。按其参考产品及数量基准缩放聚合清单，不展开原始组成过程，不重复计算已包含的上游或再次施加已完成的分配。来源引用用于追溯，不自动成为数值连接；只有 LCIA 分数的结果不作为清单输入。

发布状态、读取权限和数值输入资格分别验证，不能以 Result 类别一律拒绝符合契约的聚合过程，也不能直接放开全部结果数据。输入包须保留聚合边界、精确来源和覆盖信息；未能证明无重复计入或输入完整时返回发现，不静默修剪模型。

## 引擎与执行器

| 层次 | 责任 |
| --- | --- |
| 计算内核 | 消费完整输入，产生数值结果与诊断；不依赖业务数据库、队列或 Study 项目状态。 |
| 本地执行器 | 管理内核进程、必要运行依赖、本地状态和文件产物；无需复刻线上任务设施。 |
| 线上任务服务及 Worker | 鉴权、受理、准备输入、排队、调度、持久化、有限重试和结果访问；Worker 调用计算内核。 |

引擎标识和执行位置分别表达。具名执行配置使用一致的组织方式声明执行器类型、引擎标识、版本选择及必要的环境引用；线上和本地各自声明所需字段，不以空字段或虚构队列统一实现。

来源选择对应的默认执行配置；显式选择配置时必须与该来源的执行方式一致，否则返回不兼容错误。配置只能选择当前执行器实际支持的引擎及版本，不能因填写引擎名称而获得服务能力。默认配置必须明确可发现，不能依赖隐藏工作目录；缺失或存在歧义时给出配置指引。

实际执行前必须固定并记录引擎版本、输入身份和生效设置。线上与本地使用相同的业务输入定义和核心结果语义，不承诺不同引擎或数值环境的输出逐字节一致。可比性及数值容差由引擎契约和验证证据确定。

## 建模规则与资源预算

连接资格、单个消费端口的明确供应关系、单位一致性和适用分配属于所选引擎的建模契约。改变这些规则属于独立的语义变更，不能作为提高运行预算的副作用。

内存、超时、线程数以及输入字节数、实例数、交换项数等规模保护属于运行配置，提供可发现的默认值。本地配置优先级为单次显式覆盖、所选运行配置、引擎公布的默认值；线上请求仍受服务端上限约束。配置必须经过合法性、引擎支持和资源准入检查，拒绝不支持的值，不能静默截小。

本地规模阈值可以调整，不把固定的 64 个实例等实现默认值定义为模型规则。必须公开可调整范围、不可覆盖的实现安全上限及拒绝原因，保留内存估算、分配检查、数值检查和有界进程控制；调大配置不是可运行证明。有效预算和实际引擎版本进入结果上下文，预算调整不改变输入中的模型、方法或科学参数。扩大规模后应按相同数值标准验证，不能仅以未崩溃判定正确。

## 本地运行支撑

本地依赖的检查、准备、启动和停止归运行支撑层，计算命令消费其已声明的能力。首次下载、安装和初始化必须通过明确的准备操作完成；已准备的环境可以按显式配置自动启动。

运行支撑必须说明所需组件、版本、状态、任务创建的进程或容器、资源所有权及结束后的停止或保留策略。不得清理非本次拥有的资源。用户输入、计算结果和恢复记录不是可自动清除的运行缓存。

不要求所有引擎使用容器，不要求本地安装业务数据库或消息队列。具体运行形式由引擎依赖决定，环境实例和操作步骤放在相应运行手册中。

## 操作与结果

| 目标入口 | 意图 |
| --- | --- |
| `dataset model calculate` | 按明确模型来源计算；`--input` 承载功能单位、方法和参数等计算设置，不能再声明冲突的模型来源。 |
| `calculation get` | 使用返回的计算选择信息查询当前状态，不重新发起计算。 |
| `calculation result` | 获取并验证绑定该次输入与引擎身份的结果，大产物通过文件交付。 |

计算选择信息必须包含本地或线上范围，不能仅凭一个 ID 猜测目的地。精确请求字段通过命令帮助发现。需要取消时，仅在执行器声明支持并能确认效果时提供相应动作。

线上计算默认返回 `accepted`；可选的有界 `--wait` 在预算结束时保留任务身份并返回真实状态，不把等待结束当作任务结束。本地计算默认等待本次进程并交付结果；进程中断不意味着后台已完成。两种路径均返回实际执行方式、输入身份、引擎及版本、计算身份、状态、诊断和产物位置。

核心结果遵循[通用约定](conventions.md)和 [AI 上下文](ai-context.md)。执行状态与结果有效性、单位、方法覆盖、缺失因子、假设和限制分别保留。未产生结果时不得给出默认零值。`nextActions` 提供带真实选择信息的查询或恢复命令，`replyTemplate` 使用简单 Markdown 引用；不建立另一套工作流协议。

## 失败与恢复

- 提交响应丢失：保留原请求和目标绑定，查询或恢复原任务；不能以新请求身份重复提交。
- Worker 临时故障：线上任务服务按其有限重试策略处理并保留尝试记录，CLI 不另建重试队列或增加逻辑计算任务。
- 输入、权限或不支持的计算条件错误：返回明确诊断，不通过重试掩盖问题。修改输入后属于新的计算。
- 本地进程失败：保留诊断、已确认产物和运行状态，不默认重试；重新执行须明确记录新的尝试及其与原计算的关系。
- 结果写文件失败：保留已完成计算的身份，优先重取结果，不为了补文件再计算。

本地结果不自动进入线上 Study。未来的结果接收必须单独声明来源、验证和信任规则，服务端不能仅因上传成功就把结果认作自身计算或已审核结果。已有 Study 的版本化协议和原请求恢复记录继续按其[现行契约](../agents/study-cli-contract.md)解释，不能用新入口重写历史身份。
