# Dataset 共同接口

Dataset 操作数据集内容、身份、版本和草稿状态。入口为 `tiangong-lca dataset <type> <action>`。类型差异通过能力表和领域约束表达，共同输入输出遵循[通用约定](../conventions.md)。

## 类型与能力

下表规定本版目标接口的范围。表内支持表示设计包含该能力，不表示所有现有版本已经实现。

| 类型 | 查询与内容契约 | 本地校验与处理 | 创建、保存 | 删除草稿 | 可作为 Review 提交对象 |
| --- | --- | --- | --- | --- | --- |
| [flow](flows.md) | 支持 | 支持 | 支持 | 支持 | 支持 |
| [process](processes.md) | 支持 | 支持 | 支持 | 支持 | 支持 |
| [model](models.md) | 支持 | 支持 | 支持 | 不提供 | 支持 |
| [source](sources.md) | 支持 | 支持 | 支持 | 支持 | 支持 |
| [contact](contacts.md) | 支持 | 支持 | 支持 | 支持 | 支持 |
| [flowproperty](flowproperties.md) | 支持精确读取、列表、版本和契约 | 支持 | 普通接口不提供 | 不提供 | 不提供 |
| [unitgroup](unitgroups.md) | 支持精确读取、列表、版本和契约 | 支持 | 普通接口不提供 | 不提供 | 不提供 |
| [lciamethod](lciamethods.md) | 内容契约发现 | 结构校验 | 不提供 | 不提供 | 不提供 |

Flow、Process、Model、Source、Contact 均可通过 `review submit` 或 `review resubmit` 提交单对象或审核包，默认包含关联数据。提交能力属于 Review，不在 Dataset 类型命令下重复提供。受保护的参考数据写入只通过其独立治理接口；不能因为某类型可校验就开放普通写入。LCIA Method 的结构可发现不意味着 CLI 提供方法执行或远程 CRUD。

Model 的类型特有计算入口及独立计算记录遵循 [Model 计算设计](../calculations.md)，不将计算定义为全部 Dataset 的共同动作。LCIA Method 内容操作与计算引擎消费方法数据分别归属，存在方法 schema 不代表执行器支持该方法。

## 对象身份

远程数据身份为 `type`、`id` 和 `version`，关联所属主体、可见范围、业务状态与服务端修订凭据。命令目标身份与内容内身份不一致时拒绝执行。数据业务版本、规则版本和并发修订分别表达。

变更必须定位精确身份，不能使用 `latest`。创建时由调用方提供目标标识及业务版本，服务端验证身份和版本规则；CLI 不按名称推测复用，不自动升版。创建同一数据的新版本仍使用 `create`，显式给出新版本及来源版本身份，不复制旧审核结论或改变旧版本。复制、补全内容由调用方或明确的本地处理完成。

## 共同动作

| 动作 | 输入 | 效果与成功条件 |
| --- | --- | --- |
| `get` / `list` / `search` / `versions` | 精确身份或查询条件。 | 返回有界、可见的数据与实际版本。 |
| `contract` | 类型和所需内容。 | 返回数据结构、规则与方法资料的精确来源。 |
| `list-references` | 精确远程身份或明确本地内容。 | 列出出向引用的类型、ID、版本和出现位置，不逐一查询引用目标。 |
| `validate` | 本地内容、明确检查范围和必要证据。 | 返回结构、引用及业务规则发现，不修改数据。 |
| `create` | 新的目标身份、内容、所属主体和请求身份。 | 创建新草稿，返回实际身份、状态及验证信息。目标已存在返回冲突。 |
| `save` | 已有草稿身份、完整候选内容、预期修订和请求身份。 | 更新该草稿。目标缺失、不可见、不可修改或修订冲突时失败，不创建。 |
| `delete` | 已有草稿身份、预期修订、删除意图和请求身份。 | 在权限和引用约束允许时删除该草稿，不级联删除其他对象。 |

操作是否适用于具体类型以上表为准。读取遵循[查询与发现](../discovery.md)，确定性文件处理遵循[数据处理契约](processing.md)。`save` 输入完整内容；局部修改可直接编辑候选内容或使用本地 `patch`，再校验并保存。引用字段遵循相同方式，不另设专用修改动作。确认引用目标存在使用精确 `get`，引用关系有效性归 `validate --checks references`。

## 校验与写入

`validate` 按 `--checks schema,references,business` 选择检查，默认执行本地 schema 和可在本地完成的业务规则。依赖远程事实的检查必须显式选择，并提供认证条件或精确本地证据。结果逐项标明规则、严重程度、字段位置和未检查原因。

写入始终执行服务要求的必要检查。此前的校验报告不授予写入权限，也不允许跳过状态和并发检查。草稿可接受的内容完整度由领域规则决定；成功保存不能被描述为已经满足审核或公开使用条件。

`create` 和 `save` 不执行 upsert，也不在一条失败路径上互相切换。原创建请求的幂等恢复返回原结果，不构成另一份创建请求。`delete` 拒绝公开数据、不可删除状态和受引用约束保护的数据，不等同于撤回发布或清空账号。

写入仅改变声明的对象。引用使用明确版本，自动追新、单位换算、别名合并或下游改写都不能成为保存的隐式效果。服务端需要关联事务时必须声明其对象集合和原子保证，CLI 不用多次独立调用模拟事务。

## 与 Review 的关系

Dataset 提供被审对象的查询、创建、保存与校验。审核申请及其生命周期统一使用 [Review](../reviews.md)：`review submit` 提交，`review resubmit` 关联原审核单和新内容重新提交。

Flow、Process、Model、Source、Contact 均可独立被审，也可成为审核包成员。请求默认 `includeRelated: true`，按业务依赖规则解析关联数据；显式设为 `false` 时限定为所选对象或包内成员。包的范围、预览、内容固定及恢复统一由 Review 契约规定。

创建和保存不自动提交审核，审核提交不隐式保存修改。审核包绑定精确版本和内容修订，后续数据修改不会改变原包或自动继承原决定。数据产品发布继续使用现有 [Release](../releases.md) 接口。

## 返回上下文与后继动作

所有类型继承 [AI 上下文契约](../ai-context.md)，不另建按类型重复的回复模板。

| 操作结果 | 必须保留的上下文 | 推荐方向与表达 |
| --- | --- | --- |
| 精确读取或版本选择 | 实际对象版本、修订、可见范围和观察来源。 | 需要继续检查时使用精确身份；不能在后继重新解析 `latest`。 |
| 校验完成 | 内容身份、规则版本、执行范围、发现及未检查项。 | 使用校验模板；有问题时读取具体报告，不自动修补科学数值。 |
| 创建或保存成功 | 实际写入的身份、内容绑定、状态和可用的独立读回证据。 | 需要确认时给出 `get`；不得默认推进到审核或发布。 |
| 删除成功 | 被删除的精确身份及实际效果边界。 | 如请求已满足，可无后继动作，不默认删除关联对象。 |
| 写入冲突或结果未知 | 原请求、对象、前置条件及恢复记录。 | 冲突先读取，未知先查原请求或独立读回，不互换 create/save。 |

已有请求内容和明确意图足以支持下一动作时，返回可执行推荐；缺少输入时返回具体字段或决定，不编造请求文件。批量操作保留逐项结果与恢复身份，摘要仅表达已确认的数量和范围。

## 失败与恢复

任何远程变更的未知结果都保留原请求身份和内容绑定。返回能够执行的查询或恢复动作，不能通过重复创建、改换操作意图或更换账号消除未知状态。独立读回必须比较服务端接受的内容；仅查询到同名对象不能证明原请求成功。

```bash
# 创建明确的新版本草稿。
tiangong-lca dataset process create --input process-create.json --json

# 更新已有草稿，保存请求包含读取到的精确身份与前置修订。
tiangong-lca dataset process get --id <process-id> --version <version> --output process.json --json
tiangong-lca dataset process validate --input candidate.json --json
tiangong-lca dataset process save --input process-save.json --json

# 提交审核并使用返回的审核单查询进度。
tiangong-lca review submit --input review-request.json --json
tiangong-lca review get --id <review-id> --json
```

示例中的请求字段通过相应命令的 `--help --json` 发现。调用方根据实际状态选择动作，不将示例作为无条件工作流。
