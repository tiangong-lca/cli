## W6a/A09, W6b, and W10S CLI schema disposition

The machine-readable report is [`tidas-spec-difference-ledger.json`](./tidas-spec-difference-ledger.json), generated by `scripts/ci/compare-tidas-spec.py` from one explicit `tidas-spec` source tree. It compares parsed JSON Schema structures and records every differing JSON pointer, category, and abbreviated value/hash. `oneOf`/`anyOf`/`allOf`, `required`, and `enum` are compared with stable identities or set semantics so taxonomy insertion does not create positional noise.

The workspace decision recorded in #1240 establishes the original `tidas-tools` schema as the semantic authority; the independent `tidas-spec` repository is its reviewed carrier. The CLI package now uses a deterministic sync gate and retains the historical `assets/tidas-schemas` path for consumers.

- 18 files compared: all 18 identical and zero different.
- The pre-convergence W6a baseline had 110 differing semantic JSON locations across 11 files.
- The W10S candidate carries the four changed Process/LCIA Method schema files while the CLI synchronizer installs all 18 canonical schemas; the regenerated report has 18 identical files and zero differing or unresolved locations.
- `assets/tidas-spec-source.json` binds the installed directory to the exact spec commit, original source commit, spec version, and manifest SHA. `scripts/ci/sync-tidas-spec.py --check` fails closed on missing/extra files, manifest errors, hash drift, or identity drift.

Observed classes include dataset-version `$ref`/type changes, global-reference and classification structure changes, flow name requirements, numeric/reference constraints, LCIA normalisation and weighting types, lifecycle-model connection versions, source digital-file alternatives, and location/taxonomy membership. These labels describe the observed constraint locations; they do not decide which side is correct.

## Reproduction

From the CLI repository root:

```bash
python3 scripts/ci/test-sync-tidas-spec.py
python3 scripts/ci/sync-tidas-spec.py \
  --spec-root ../tidas-spec \
  --spec-commit 58dc72f5cb2d203a00388fec71d31091911f7dde \
  --check
python3 scripts/ci/test-compare-tidas-spec.py
python3 scripts/ci/compare-tidas-spec.py \
  --spec-root ../tidas-spec \
  --cli-commit 7a7e2c94ae57beecae4e8f6f90ffcadd277f08a4 \
  --check docs/agents/tidas-spec-difference-ledger.json
```

The comparator and synchronizer fail if the selected source tree, file set, parsed content, or report metadata changes. A changed report requires re-running the source qualification; it is not a reason to silently regenerate installed assets.

## W6b handoff and fixture evidence

W6b is implemented for the canonical-source decision.
