# CLI 0.2.0 重构实施计划

本计划规定 CLI 自身重构的实施顺序、依赖、阶段产物与验收条件。[目标接口设计](../interfaces/README.md)规定最终行为，[现有能力对照](../analysis/cli-interface-comparison.md)记录实现差距；本文件不重新定义接口。

计划基于 2026-11-08 确认的设计：运行代码基线为 CLI `0.1.29`、提交 `5fcde75e54220e6fca0015b85f2a5c7996c50ba4`，初始设计基线为提交 `22cb236`，并包含后续确认的引用接口收敛：保留 `list-references`，目标存在性使用精确 `get`，关系校验归 `validate`，修改归编辑或通用 `patch` 后独立保存。具体工作分支和本轮操作授权记录在对应 Issue 中。实施从 README、AGENTS 和真实样例建立分层开始，再迁移 Dataset 与现有 Review 业务。当前能力以 README、命令帮助和验证记录为准；目标设计中的后续审核扩展不作为本次已有业务迁移的完成条件。

## 范围与交付边界

本次交付包括：

- CLI 核心命令、业务适配及公共输入输出的重构。
- 目标类型能力、独立创建与保存、审核接口及 AI Friendly 上下文。
- CLI 内部旧入口和无用实现的清理，以及原有通用执行、身份、运行支撑和恢复能力的保留。
- 自动化测试、安装包验收、接口文档和发布后供下游使用的迁移说明。

下游调用方迁移不属于本次范围。Foundry、Utilities、Agent Skills、MCP 等调用方在 CLI Release 后分别安排迁移；本次不修改其代码、版本固定或工作流，也不以其接入或迁移完成作为 CLI 验收条件。测试可以借鉴下游使用情景，由 CLI 仓库内的测试程序组合新命令，不把这些流程重新实现为 CLI 业务编排。

以下内容不纳入本轮实现：

- 现有 `release` 命令的优化、改名或结果协议改造；保留行为并做回归验证。
- 新的跨类型 `dataset package` 命令组织；既有转换和整包校验入口按现有范围保留。
- 研究、数据生产计划、AI 内容生成、证据取舍和专项运维流程在其他仓库的重建。
- 无关的依赖升级、通用 Agent 任务引擎、多账号管理平台或复杂模板协议。

服务端缺口与下游迁移分别处理。CLI 目标能力所必需的服务契约需要提前核实；缺失的后端能力由所属仓库另行交付，作为对应 CLI 能力的外部依赖，不在 CLI 内模拟权限、事务或审核状态。尚未满足的依赖必须保留为阻断项，不能通过 mock 测试宣称真实能力已完成。

本计划的终点是可供评审的 CLI 0.2.0 候选版本。代码集成、正式发布和 workspace 集成遵循对应的交付流程，具体执行状态记录在 Issue/PR 中。

### 场景验收

- 用有明确预期值的模型，将一个前景过程连接到已知参考量的聚合背景清单，核对缩放、清单和 LCIA；其原始组成过程即使可访问也不重复计入，不再次应用已完成的分配。
- 覆盖前景直接排放、多个独立需求复用背景、残余未闭合交换、方法数据损坏、正常稀疏因子、单位不匹配及来源不可见；不以静默截断或默认零制造成功。
- 对状态 100 Process 及其 HDF5 结果验证“可发现—精确版本结果解析—完整 LCI 读取—准备—计算”路径；覆盖独立 Result 身份、多结果选择、分页为空但有游标、发布或运行版本变化、参考量缩放及单位匹配。仅有指标分数、不完整结果和权限拒绝不能进入计算；读取授权不升级为修改或发布权限。
- 本地固定输入在禁止网络且无数据库/队列时完成计算；覆盖组件未安装、方法缓存缺失、预算覆盖、扩大模型规模、进程中断、产物重取和任务拥有资源清理。
- 对相同固定输入及引擎版本比较线上与本地结果，按引擎声明的数值标准验收；分别记录真实服务、原生执行和模拟测试证据。
- Study 使用代表性资料验证统计口径与来源提取、关键缺口追问、背景选择依据及最小范围修订；计算成功不自动触发数据集发布或报告分享。

命令帮助、简单下一步提示和回复模板随实际能力交付。已有 Study 协议及历史恢复文件保持原含义；背景聚合数据的消费不等于接收并信任用户上传的计算结果。本地结果上传接收、跨位置提交和既有调用方迁移另行确定范围。跨仓变更在各自所有者仓库交付，并分别记录源码验证、发布和 workspace 集成状态。

## 1. 优化 README

README 面向使用者，说明项目定位、四类职责、安装与起步、新命令组织和专题文档入口。明确区分已发布版本、分支已实现能力和目标设计，避免把未实现命令写成可执行教程。原有使用说明与历史记录保留到独立参考文档，现有入口仍可查阅。

完成条件：使用者能从简短入口判断当前版本可做什么、如何开始、详细行为在哪里查。

## 2. 优化 AGENTS

AGENTS 面向开发 AI，规定目录职责、依赖方向、新命令开发路径、测试和文档要求。保留认证、权限、写入恢复、科学规则、公共库和发布约束；具体命令的详细约束移入可路由的专题契约，不因精简入口而失效。

完成条件：新增命令的归属和验收路径明确，现有约束仍能按需发现，新旧文档无冲突。

## 3. 搭建最小框架结构

划分 `src/commands`（入口与参数）、`src/application`（业务操作与端口）、`src/adapters`（服务适配）和 `src/shared`（公共结果、文件及呈现）。入口组合依赖，业务层不处理 argv 或 IO，适配层复用已验证的现有能力。`src/lib` 逐步迁移，不进行大规模机械搬迁，不创建空领域目录或插件框架。

完成条件：目录包含真实职责，完整源码边界和运行时循环由测试检查，生产默认依赖在组合入口选择；业务判断、IO 与命令呈现分别归属。既有保留协议和公共导出保持可用；新增目录和模板资产纳入 Docpact 路由。

## 前置核查：命令迁移清单与服务依赖表

以现有能力对照为起点，逐项核对实际命令分派、实现、帮助和测试。清单至少记录：旧入口、目标入口、实现位置、复用或新增内容、保留或删除结论、行为差异、外部依赖和验收情景。记录已知下游使用方式，用于迁移说明和测试选例，不生成下游改造任务。

优先核实三组依赖：

- Dataset 写入的精确身份、前置状态校验、请求身份及结果查询或独立读回能力。
- Model 与结果 Process 的关联保存范围、事务保证及创建冲突行为。
- Review 的关联范围解析、内容固定、权限、轮次、决定、材料与未知结果恢复能力。

产物是命令迁移清单、服务依赖表和验收场景清单，均在 `docs/interfaces/` 之外维护。每项外部依赖记录实际接口来源、能力差距、所属仓库和验证方式。不能把“CLI 尚未接入”直接判断为“服务端没有实现”。

完成条件：目标能力均有实现路径或明确阻断项；保留范围和待移除范围清楚；后续阶段无需重新推断核心职责。

## 4. 用真实命令验证框架

使用 `dataset process get` 和 `dataset process validate` 验证参数解析、命令发现、结构化帮助、业务执行、错误、退出码、文件输出及结果呈现。逐步分离命令入口、业务操作和输出逻辑，复用现有数据读取与校验能力。

公共接口遵循[通用约定](../interfaces/conventions.md)和 [AI 上下文设计](../interfaces/ai-context.md)：

- JSON stdout 只返回约定的结果；诊断进入 stderr。
- 实际对象、版本、输入、默认值、完整性和未检查项可见。
- `nextActions` 每项只包含说明和可选命令；没有有用动作时为空数组。
- `replyTemplate` 只提供 Markdown 文件路径；模板随安装包分发，不引入注册元数据或占位符解析协议。
- 人类输出与 JSON 表达相同的业务事实，大内容通过文件或分页交付。

完成条件：两个真实命令在成功、输入错误、校验失败或读取失败等结果下均符合契约；安装包在源码目录之外可调用，模板路径可读取。只提取已被样例证明必要的公共能力，不预先搭建大型命令框架。

## 5. 迁移查询、发现、环境与认证

按[类型能力表](../interfaces/datasets/README.md)迁移 `get/list/search/versions/contract/list-references`，以及分类目录查询。Flow、Process、Model、Source、Contact 按各自设计开放入口；Flow Property、Unit Group 保持参考数据范围；LCIA Method 仅提供设计规定的内容契约与结构校验，不因共享实现而开放远程 CRUD。

`list-references` 返回当前内容的引用类型、ID、版本及出现位置，不递归展开或逐一请求引用目标。以本地输入无网络请求、远程输入只读取所选对象作为验收条件；目标存在性由调用方按需执行精确 `get`。

统一分页、过滤、字段投影、精确版本和候选表达。`latest` 的解析结果必须可见，后续动作使用实际版本；多个候选不默认选中首项；读取失败或范围不完整不能伪装为空集合。

环境和认证复用现有 OAuth、会话及身份验证实现，接入目标帮助与结果表达，补齐明确的行为差异。区分本地状态与在线核验；运行支撑保持独立发现，子进程透传不强行套用业务结果协议。

完成条件：类型能力与帮助一致；分页和版本发现可验证；身份、环境和观察来源准确；查询或诊断不隐式修改业务数据、安装组件或切换账号。

## 6. 迁移校验与确定性数据处理

按类型逐步迁移 `validate/diff/patch/translations`，再接入 Process 统计、Model 图与生成模型结果过程等特有操作。复用已有算法、规则和类型校验，解除对私有运行目录、阶段文件及隐式选择的依赖。

明确输入文件、输出产物、检查范围和引用证据。引用关系检查统一进入 `validate --checks references`，远程检查显式声明；引用字段允许直接编辑或使用通用 `patch`，按需独立 `save`，不新增专用检查或改写入口。补丁和翻译回填验证源内容及定位；聚合只生成候选 Process，不自动保存、提交审核或发布。Source 附件传输保持独立效果，上传成功与 Source 保存成功分别表达。

Flow 参考属性的本地业务约束由同一纯校验器承载：内部 ID 有效且唯一，声明的参考指针唯一可解析，全部因子有限且为正，参考因子精确等于十进制 1。类型化校验、写入准入、维护计划/新写入前检及包校验复用规则；校验不自动归一化、换算或替换指针。保持结构与内容诊断分层，并验证历史成功恢复不重放。

契约验收同时覆盖 Unit Group 的局部身份与参考解析、Source 附件和数据集引用的区分、Process 交换项投影及统计过滤/分组、所有未执行检查的披露。统计完整性和内容投影不得由命令正常完成推断。命令帮助提供实际请求字段，公共规则发现不混入退役工作流策略；续页、文件保护、上下文大小和结果模板分别通过实际入口验证。

模型结果生成以 `dataset model build-resulting-process` 为主命令，`dataset model aggregate` 为长期支持的别名，两者共用参数解析、帮助契约、业务实现、结果呈现和测试用例。文档示例、推荐命令及结果中的 `operation` 统一采用主命令。验收使用两种入口运行相同成功、输入错误和业务失败用例，核对业务产物、默认值、结果语义、错误、退出码及规范化的动作名称一致，避免分别维护两套实现和测试。

完成条件：命令可以脱离原生产工作流独立运行；相同确定性输入产生可比对的业务产物；错误、缺失证据和不适用规则准确表达；科学规则不因重构而退化。全部类型特有动作均有归属和验证，不能只完成共同动作。

## 7. 分离并迁移 Dataset 写入

从一种普通可编辑对象开始验证完整写入行为，再扩展到其他类型；Model 单独验证关联一致性。`create` 创建明确的新草稿身份，`save` 更新精确已有草稿，`delete` 只处理类型能力表允许删除的草稿。

重点验证：

- 创建遇到冲突不改成更新，保存遇到缺失不改成创建；包括移除现有 Model 的创建冲突后更新路径。
- 对象身份、内容、预期状态、账号、环境和请求身份绑定一致。
- 前置状态冲突由服务端验证；必要的关联事务不使用多次独立调用伪装。
- 派发后未知结果保留原请求恢复信息，不自动重试或更换写入意图。
- 保存不自动追新引用、修改关联对象或提交审核；删除不级联清理账号。
- 批量保留逐项结果、同对象串行及未知状态，不宣称整体事务。

完成条件：创建、保存、允许的删除及独立读回均有验证；冲突、权限失败、部分完成和超时恢复有覆盖；只读参考类型和 Model 删除等设计外能力未被开放。普通保存保留服务端内容 CAS；Model 保存与草稿删除沿用既有业务语义，内容比较仅发生在前检时必须明确披露，不以本地判断宣称服务端 CAS。

## 8. 迁移现有 Review 业务接口

本次以已有业务服务为实施基线，先迁移单起始对象及服务端关联提交、驳回后的重新提交、当前审核查询和材料、审核草稿保存及审核者决定。服务契约依据见[能力对照](../analysis/cli-interface-comparison.md#现有业务服务与本次实施基线)。

五种可审核类型共用提交入口，`includeRelated` 默认且仅支持 `true`。服务端决定关联范围、实际审核单和提交模式；结果保留这些真实信息，不将多个单对象请求组合后宣称整包原子提交。预览只检查可读前提，明确未执行的关联展开及写入时准入。

最终 Review 目标仍规定追加式意见、历史轮次材料和不可变包；本阶段的草稿保存与当前可读内容是明确的实现子集，不将目标文档缩减为现有服务语义。

`resubmit` 前检已驳回审核及同一精确对象，保留调用方修改说明，不伪造服务端轮次关联。`get/list/materials` 表达当前可见记录及材料；历史不可变包和一致多对象快照不在此阶段承诺。`comment` 保存当前审核者草稿，明确可能覆盖；`decide` 单独提交实际审核者决定，保留 Process/Model 需要已有草稿等业务前提。

目标设计中的关闭关联、明确多起始对象审核包、历史包重取、轮次关联、追加式独立意见及没有既有服务映射的审核撤回，后续由业务所有者实施，不纳入本次验收。CLI 不新增后端契约或用其他操作冒充这些效果。

完成条件：既有提交者和审核者情景通过协议适配与安装验证；内容、权限、状态和真实效果不被客户端推断替代；未知结果不重复提交。真实账号集成证据与协议模拟分别记录，未获授权的真实写入不作为已执行验证。

## 10. 安装包与业务场景整体验收

各阶段持续增加相应测试；本阶段验证命令之间的组合、安装分发和最终覆盖，不把全部测试推迟到末尾。使用仓库现有测试框架，并按[仓库验证契约](../agents/repo-validation.md)执行适用检查；最终执行 `pnpm prepush:gate`，维持既有完整覆盖率及安装包验证要求，完成适用的跨平台验证。

| 情景 | 命令组合或操作 | 核心断言 |
| --- | --- | --- |
| 列出并确认引用对象 | list-references、精确 get，必要时版本发现 | 清单保留引用位置，不逐一请求目标；目标存在及可访问由 get 确认；缺失信息不猜测。 |
| 修改并校验引用关系 | 直接编辑或通用 patch、validate、独立 save | 目标存在但关系不匹配时校验失败；修改不自动追新或换算，未 save 前不改变远程内容。 |
| 准备并创建数据 | 契约发现、本地校验、create、get | 内容与身份一致；冲突不更新已有对象；读回验证实际效果。 |
| Flow 参考属性约束 | validate、create/save、维护计划/前检、包校验 | 单项/数组和非首项 ID 定位正确；零、负数、缺失/重复 ID、悬空指针及近似 1 返回字段问题；无隐式修正，失败不派发写入；源码外安装包使用相同规则。 |

| 上传 Source 附件 | 上传、候选内容检查、独立 save | 上传与保存分别有结果；保存失败不误报整个操作完成。 |

| 拒绝未实施审核扩展 | includeRelated 为 false、多个起始对象或历史轮次 | 无任何写入，明确说明后续目标能力及已有服务边界。 |

完成条件：目标能力、类型差异和关键失败路径均有测试或集成证据；未执行检查明确记录；必要依赖与阻断项已解决；接口文档和迁移说明与候选包一致。下游迁移完成不在此验收清单中。

## 架构验收

- Dataset/Review 写入由 application 组织前置检查、效果和回执判断，适配器实现明确 IO 端口；推荐命令由命令层构造。

- 边界测试覆盖全部源码及运行时导入图，行为与安装包测试继续在原有 100% 门禁下验证。普通维护保留准入与恢复保护；专项修复入口及专属实现退役，历史证据由匹配原版本解释。

## 错误结果与能力发现验收
