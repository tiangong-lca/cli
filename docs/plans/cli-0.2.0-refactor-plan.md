# CLI 0.2.0 重构实施计划

本计划规定 CLI 自身重构的实施顺序、依赖、阶段产物与验收条件。[目标接口设计](../interfaces/README.md)规定最终行为，[现有能力对照](../analysis/cli-interface-comparison.md)记录实现差距；本文件不重新定义接口。

计划基于 2026-11-08 确认的设计：运行代码基线为 CLI `0.1.29`、提交 `5fcde75e54220e6fca0015b85f2a5c7996c50ba4`，设计基线为提交 `22cb236`。工作分支为 `refactor-0.2.0`。当前仅完成计划编写，下列八个实施阶段均未开始；文档示例不代表对应命令已实现。

## 范围与交付边界

本次交付包括：

- CLI 核心命令、业务适配及公共输入输出的重构。
- 目标类型能力、独立创建与保存、审核接口及 AI Friendly 上下文。
- CLI 内部旧入口和无用实现的清理，以及原有通用执行、身份、运行支撑和恢复能力的保留。
- 自动化测试、安装包验收、接口文档和发布后供下游使用的迁移说明。

下游调用方迁移不属于本次范围。Foundry、Utilities、Agent Skills、MCP 等调用方在 CLI Release 后分别安排迁移；本次不修改其代码、版本固定或工作流，也不以其接入或迁移完成作为 CLI 验收条件。测试可以借鉴下游使用情景，由 CLI 仓库内的测试程序组合新命令，不把这些流程重新实现为 CLI 业务编排。

以下内容不纳入本轮实现：

- 现有 `release` 命令的优化、改名或结果协议改造；保留行为并做回归验证。
- 新的跨类型 `dataset package` 命令组织；既有转换和整包校验入口按现有范围保留。
- 研究、数据生产计划、AI 内容生成、证据取舍和专项运维流程在其他仓库的重建。
- 无关的依赖升级、通用 Agent 任务引擎、多账号管理平台或复杂模板协议。

服务端缺口与下游迁移分别处理。CLI 目标能力所必需的服务契约需要提前核实；缺失的后端能力由所属仓库另行交付，作为对应 CLI 能力的外部依赖，不在 CLI 内模拟权限、事务或审核状态。尚未满足的依赖必须保留为阻断项，不能通过 mock 测试宣称真实能力已完成。

本计划的终点是可供评审的 CLI 0.2.0 候选版本。合入 `main`、正式发布和后续 workspace 集成按各自交付流程另行安排；执行本计划不自动授权这些动作。

## 实施顺序

| 步骤 | 主题 | 前置条件 | 可验收产物 |
| --- | --- | --- | --- |
| 1 | 建立命令迁移清单与服务依赖表 | 已确认目标设计 | 每项能力的实现路径、差距、依赖和测试情景。 |
| 2 | 最小公共接口与完整样例 | 第 1 步的首批能力可实现 | Process 读取、校验贯穿新接口及安装包。 |
| 3 | 查询、发现、环境与认证 | 第 2 步公共接口可复用 | 按类型能力表开放的查询入口与准确的身份、环境结果。 |
| 4 | 校验与确定性数据处理 | 第 2 步；需要远程事实的部分依赖第 3 步 | 可独立调用、无隐式远程写入的数据处理能力。 |
| 5 | Dataset 独立写入 | 第 3、4 步及已验证的服务端写入契约 | 独立的 create、save、delete 及异常恢复。 |
| 6 | Review 接口 | 第 3 步及审核服务契约；完整场景依赖第 5 步 | 单对象和审核包的提交、处理与查询。 |
| 7 | 清理旧入口与准备迁移说明 | 对应新能力通过验收 | 收敛后的 CLI 命令树和下游迁移资料。 |
| 8 | 安装包与业务场景整体验收 | 第 3～7 步完成，必需服务依赖可验证 | 目标能力覆盖与可评审候选版本证据。 |

服务端核查从第 1 步开始，不等到第 6 步才发现审核依赖。第 3、4 步可按依赖拆分推进；第 6 步的查询适配可以提前开展。第 7 步的清理随已验收能力逐批进行，最终统一检查残留。每个阶段可以拆成多个小提交，阶段编号不等于提交数量。

## 1. 建立命令迁移清单与服务依赖表

以现有能力对照为起点，逐项核对实际命令分派、实现、帮助和测试。清单至少记录：旧入口、目标入口、实现位置、复用或新增内容、保留或删除结论、行为差异、外部依赖和验收情景。记录已知下游使用方式，用于迁移说明和测试选例，不生成下游改造任务。

优先核实三组依赖：

- Dataset 写入的精确身份、前置状态校验、请求身份及结果查询或独立读回能力。
- Model 与结果 Process 的关联保存范围、事务保证及创建冲突行为。
- Review 的关联范围解析、内容固定、权限、轮次、决定、材料与未知结果恢复能力。

产物是命令迁移清单、服务依赖表和验收场景清单，均在 `docs/interfaces/` 之外维护。每项外部依赖记录实际接口来源、能力差距、所属仓库和验证方式。不能把“CLI 尚未接入”直接判断为“服务端没有实现”。

完成条件：目标能力均有实现路径或明确阻断项；保留范围和待移除范围清楚；后续阶段无需重新推断核心职责。

## 2. 建立最小公共接口，跑通完整样例

使用 `dataset process get` 和 `dataset process validate` 验证参数解析、命令发现、结构化帮助、业务执行、错误、退出码、文件输出及结果呈现。逐步分离命令入口、业务操作和输出逻辑，复用现有数据读取与校验能力。

公共接口遵循[通用约定](../interfaces/conventions.md)和 [AI 上下文设计](../interfaces/ai-context.md)：

- JSON stdout 只返回约定的结果；诊断进入 stderr。
- 实际对象、版本、输入、默认值、完整性和未检查项可见。
- `nextActions` 每项只包含说明和可选命令；没有有用动作时为空数组。
- `replyTemplate` 只提供 Markdown 文件路径；模板随安装包分发，不引入注册元数据或占位符解析协议。
- 人类输出与 JSON 表达相同的业务事实，大内容通过文件或分页交付。

完成条件：两个真实命令在成功、输入错误、校验失败或读取失败等结果下均符合契约；安装包在源码目录之外可调用，模板路径可读取。只提取已被样例证明必要的公共能力，不预先搭建大型命令框架。

## 3. 迁移查询、发现、环境与认证

按[类型能力表](../interfaces/datasets/README.md)迁移 `get/list/search/versions/contract`，以及分类目录查询。Flow、Process、Model、Source、Contact 按各自设计开放入口；Flow Property、Unit Group 保持参考数据范围；LCIA Method 仅提供设计规定的内容契约与结构校验，不因共享实现而开放远程 CRUD。

统一分页、过滤、字段投影、精确版本和候选表达。`latest` 的解析结果必须可见，后续动作使用实际版本；多个候选不默认选中首项；读取失败或范围不完整不能伪装为空集合。

环境和认证复用现有 OAuth、会话及身份验证实现，接入目标帮助与结果表达，补齐明确的行为差异。区分本地状态与在线核验；运行支撑保持独立发现，子进程透传不强行套用业务结果协议。

完成条件：类型能力与帮助一致；分页和版本发现可验证；身份、环境和观察来源准确；查询或诊断不隐式修改业务数据、安装组件或切换账号。

## 4. 迁移校验与确定性数据处理

按类型逐步迁移 `validate/diff/patch/references/translations`，再接入 Process 统计、Model 图与聚合等特有操作。复用已有算法、规则和类型校验，解除对私有运行目录、阶段文件及隐式选择的依赖。

明确输入文件、输出产物、检查范围和引用证据。远程引用检查显式声明；补丁和翻译回填验证源内容及定位；聚合只生成候选 Process，不自动保存、提交审核或发布。Source 附件传输保持独立效果，上传成功与 Source 保存成功分别表达。

完成条件：命令可以脱离原生产工作流独立运行；相同确定性输入产生可比对的业务产物；错误、缺失证据和不适用规则准确表达；科学规则不因重构而退化。全部类型特有动作均有归属和验证，不能只完成共同动作。

## 5. 分离并迁移 Dataset 写入

从一种普通可编辑对象开始验证完整写入行为，再扩展到其他类型；Model 单独验证关联一致性。`create` 创建明确的新草稿身份，`save` 更新精确已有草稿，`delete` 只处理类型能力表允许删除的草稿。

重点验证：

- 创建遇到冲突不改成更新，保存遇到缺失不改成创建；包括移除现有 Model 的创建冲突后更新路径。
- 对象身份、内容、预期状态、账号、环境和请求身份绑定一致。
- 前置状态冲突由服务端验证；必要的关联事务不使用多次独立调用伪装。
- 派发后未知结果保留原请求恢复信息，不自动重试或更换写入意图。
- 保存不自动追新引用、修改关联对象或提交审核；删除不级联清理账号。
- 批量保留逐项结果、同对象串行及未知状态，不宣称整体事务。

完成条件：创建、保存、允许的删除及独立读回均有验证；冲突、权限失败、部分完成和超时恢复有覆盖；只读参考类型和 Model 删除等设计外能力未被开放。服务端不能保证的必要条件仍作为阻断项，不以 CLI 本地判断替代。

## 6. 实现 Review 领域接口

按以下次序交付：

1. 查询与材料：`get/list/materials`。
2. 提交与重新提交：`submit/resubmit`，包含可选 `--dry-run`。
3. 处理：`comment/decide/withdraw`。

五种可审核对象共用入口。单对象通过明确选择及 `includeRelated: false` 实现；默认 `includeRelated: true` 解析必要关联数据。起始对象、被审成员与参考材料分别表达；循环去重、缺失引用、权限不足、内容冲突和展开上限不得形成静默的不完整提交。

按[审核设计](../interfaces/reviews.md)验证包内容固定、可重取、预览摘要绑定、新旧轮次关系、成员与整包状态、实际允许动作及原请求恢复。提交不隐式保存数据，已受理不代表审核通过，单个成员通过不代表整包完成。专业决定和权限由授权主体及领域服务承担。

完成条件：提交者和审核者情景都可通过实际服务契约验证；后续保存不能改变已提交内容；重新提交保留历史；未知结果不重复创建审核单或记录决定。仅有模拟响应不满足此阶段的服务集成验收。

## 7. 清理旧入口，准备下游迁移说明

按第 1 步清单，删除已被替代的入口、帮助及无引用实现，收敛核心命令树。研究、生产编排及专项运维流程退出核心范围时，在本仓完成入口和依赖清理，并记录移除后的使用边界；本次不在下游仓库重建这些流程。

语义完全一致的入口在分支开发期间可以临时转接；upsert、隐式保存、自动追新等旧行为不能直接映射成新动作。所有过渡入口在验收前明确最终处置，不保留没有退出条件的兼容层。旧恢复记录、历史产物及公共库接口的兼容需求单独核查，不能随命令清理误删恢复能力。

下游迁移说明包括旧命令到新命令映射、移除项、参数与输出变化、创建和保存的语义差异、错误与恢复方式，以及基于新命令的使用示例。无法一对一映射的旧流程说明应由调用方组合哪些原子能力，不伪造等价替代命令。

完成条件：核心入口符合设计，保留能力可用，删除理由和迁移资料完整。下游代码更新、版本升级、接入和迁移验收均在 CLI Release 后独立进行，不属于本阶段完成条件。

## 8. 安装包与业务场景整体验收

各阶段持续增加相应测试；本阶段验证命令之间的组合、安装分发和最终覆盖，不把全部测试推迟到末尾。使用仓库现有测试框架，并按[仓库验证契约](../agents/repo-validation.md)执行适用检查；最终执行 `pnpm prepush:gate`，维持既有完整覆盖率及安装包验证要求，完成适用的跨平台验证。

| 情景 | 命令组合或操作 | 核心断言 |
| --- | --- | --- |
| 查找引用对象 | 检索、读取、版本发现、引用检查 | 候选不自动选定，版本精确，分页与权限范围完整。 |
| 准备并创建数据 | 契约发现、本地校验、create、get | 内容与身份一致；冲突不更新已有对象；读回验证实际效果。 |
| 修改已有草稿 | get、patch、validate、save、get | 前置状态被验证；并发变化返回冲突；缺失目标不创建。 |
| 聚合模型生成 Process | graph、aggregate、validate、独立 create 或 save | 依赖与投影明确，产物可追溯，聚合本身不写入。 |
| 上传 Source 附件 | 上传、候选内容检查、独立 save | 上传与保存分别有结果；保存失败不误报整个操作完成。 |
| 提交关联审核包 | submit 预览、submit、get、materials | 默认关联范围正确；精确包内容可重取；缺失依赖阻断。 |
| 提交单对象审核 | 五种可审核类型分别指定 includeRelated 为 false | 仅所选对象为被审成员，必要引用仍检查。 |
| 处理意见并重新提交 | comment、Dataset save、resubmit、get | 旧包不变，新轮次与内容绑定明确，历史决定不复制。 |
| 审核者处理 | list、materials、comment、decide | 成员与整包状态区分，权限及轮次冲突不能绕过。 |
| 写入超时后继续 | 注入派发后超时，按原请求查询或独立读回 | 未知效果不当作未执行，不重复创建、提交或记录决定。 |
| AI 根据结果继续操作 | 读取 JSON、模板和 nextActions | 推荐带真实参数；缺输入只说明；模板缺失不改变结果或重放操作。 |
| 安装与保留能力回归 | 源码目录外调用、环境与认证、runtime/PCR、Release | 模板和产物可访问；公共库接口可用；Release 原行为保持。 |

下游情景取自已核实的使用方式，记录来源和所验证的目标行为；使用脱敏或合成数据构造可重复 fixture。上表定义待实现的验收情景，不声称均已有下游真实案例或测试证据。测试程序负责串联原子命令，CLI 不新增生产任务状态机。

区分单元测试、协议模拟、安装包测试和真实服务集成证据。网络中断、冲突、权限拒绝和部分结果使用可控故障验证；真实服务场景使用获授权的测试环境和可清理数据。模拟测试通过不代表服务权限、内容快照或事务保证已得到验证。

完成条件：目标能力、类型差异和关键失败路径均有测试或集成证据；未执行检查明确记录；必要依赖与阻断项已解决；接口文档和迁移说明与候选包一致。下游迁移完成不在此验收清单中。

下一项工作是第 1 步的逐命令迁移清单与服务依赖核查。正式发布后，下游依据迁移说明独立推进升级。
